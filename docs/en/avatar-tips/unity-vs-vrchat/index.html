Avatar Tips #13

It looks different in Unity and VRChat

The expression or body shape you set up in Unity is back to the original once you're in VRChat. Most of the time, that's because the FX Animator is overwriting the BlendShape (shape key) values. This tip explains why they get overwritten, where to look, and how to fix it.

Read this when

  • You changed your expression by moving BlendShapes in Unity, but in VRChat your face goes back to the original.
  • You shrank your body to fit an outfit, but in VRChat your body pokes through the outfit.
  • When you change hand gestures, your body shape or blush changes along with your expression.
  • Once a hand gesture changes your expression, the expression stays even after you put your hand back.

The main reasons it looks different

There are several reasons your avatar can look different in Unity and VRChat. This tip covers the most common one, number 1, in detail.

1. The Animator overwrites values
In VRChat, your avatar's Animators (especially FX) run, and every frame they overwrite BlendShapes and other values with the values written in animations. In Unity's editor, the Animator isn't running. This is what this tip is about.
2. BlendShapes that VRChat moves
VRChat moves blinking and mouth shapes (Visemes). BlendShapes set in Eye Look or Lip Sync on the VRC Avatar Descriptor get overwritten, even if you set values for them in Unity.
3. Swaying parts (PhysBone)
Swaying parts don't move while you're editing in Unity, so hair and skirts stay in the shape they were made in. In VRChat, gravity and other forces change their shape. They do move when you press Play in Unity.
4. Brightness and color
The lights in your Unity scene are different from a world's lights. Brightness, color and shadows change from world to world.
5. The viewer's settings and device
If a viewer's Safety settings block shaders, your avatar looks different to them. On Quest and phones, people see the version made for their device, or a stand-in.
6. Draw order
When transparent parts overlap a world's transparent things, how they look depends on the draw order. #14 Render Queue (draw order)

In Unity's editor, the Animator isn't running

When Unity isn't in Play mode, what you see is exactly the values you entered in the BlendShapes section of the Skinned Mesh Renderer. The Animator isn't running.

When VRChat loads your avatar, the Animator starts running. Every frame, it writes over everything with the values in the animation (clip) of the state it's currently in. The values you entered in Unity get overwritten each time.

In other words, if a BlendShape is written in any clip, the Animator decides its value. You only see the Skinned Mesh Renderer's value as-is when the Animator writes nothing to that BlendShape.

  1. The value you set in Unityeye_smile = 60 on the Skinned Mesh Renderer
  2. VRChat loads the avatarThe Animator starts running
  3. The FX Idle stateIts clip writes eye_smile = 0
  4. What you seeeye_smile = 0 (different from Unity)
  1. A value you entered to change your expression. If an FX clip writes eye_smile, VRChat uses that clip's value instead.
  2. A value you entered to shrink your body to fit an outfit. If the outfit toggle clips write shrink_chest, VRChat uses those clips' value instead.

What Write Defaults changes

The Animator takes charge of every property that appears in any clip in the controller. If the current state's clip has that property, the Animator writes its value. Write Defaults on the state decides what to write when the clip doesn't have it.

Write Defaults ONWrite Defaults OFF
Written in the clipThe clip's valueThe clip's value
Not written in the clipThe default value (the value when the avatar loaded, meaning the value you had set in Unity when you uploaded)Writes nothing (the last value written stays)

Avatars with Write Defaults OFF often have a clip that sets all expression BlendShapes to 0 in the state used when nothing is happening (Idle), so expressions from hand gestures don't stick. This clip also resets the values you set in Unity to 0.

When several layers write the same BlendShape, the lower layer wins.

Change the value set in Unity, Write Defaults, and the current state, and see how the avatar looks in VRChat. When you change the value, it counts as a fresh upload and starts over.

Common problems and how to fix them

Your changed expression goes back

What happens
You moved eye or mouth BlendShapes in Unity to change your usual expression. In VRChat, it goes back to the original.
Cause
The clip in the FX Idle state (the state used when nothing is happening) writes that BlendShape.
How to fix it
Change the value in that clip to the value you set in Unity. If Write Defaults is ON, you can also delete that line from the clip.

Your shrunk body pokes through the outfit

What happens
You moved a body BlendShape (for shrinking) to fit an outfit. In VRChat, your body goes back to its original shape and pokes through the outfit.
Cause
The clips that toggle the outfit also write the body's shrink BlendShape (for example, 100 when the outfit is on and 0 when it's off). The value in the current state's clip is used.
How to fix it
Match the shrink value in the outfit toggle clips. Write the value you set in Unity into the clip for when the outfit is on.

Hand gestures change unrelated things

What happens
When you change your expression with a hand gesture, your body shape or blush changes too.
Cause
The expression clip has lines for BlendShapes that have nothing to do with the expression.
How to fix it
Delete the unrelated lines from the expression clip. If Write Defaults is OFF, also check that no values stay behind after you delete them.

Your expression doesn't go back

What happens
After you change your expression with a hand gesture, it doesn't go back when you put your hand back.
Cause
Write Defaults is OFF and the Idle clip doesn't have that BlendShape, so the value written by the hand gesture stays.
How to fix it
Add a line to the Idle clip that writes that BlendShape at its usual value.

Find the clip that causes it

First, press Play in Unity and see whether the same thing happens as in VRChat. With Gesture Manager, which you can add from the VRChat Creator Companion, the Animator runs when you press Play in Unity, and you can try hand gestures too. If the value goes back when you play, the Animator is the cause.

  1. Select your avatar in the Hierarchy. In the Inspector, check which controller is set for FX under "Playable Layers" on the VRC Avatar Descriptor.
  2. Double-click that controller to open it in the Animator window. The layers are listed under Layers on the left.
  3. Select the layers one at a time and click the orange state (the state it enters first). The state's clip appears in Motion in the Inspector.
  4. Select the clip and look inside it in the Animation window (Window → Animation → Animation). If there's a line like Body : Blend Shape.eye_smile, that clip writes that BlendShape.
  5. Check the states entered from hand gestures and the menu the same way.
  1. You set eye_smile to 60 in Unity, but this clip writes it as 0. While you're in Idle in VRChat, eye_smile is 0.
  2. Sometimes the clip also has body BlendShapes that have nothing to do with expressions. If Write Defaults is ON, deleting this line brings back the value you set in Unity.

How to fix it

  1. Before you fix anything, make sure you can go back. Duplicate the clip, or export your avatar's folder.
  2. Open the clip that causes it in the Animation window, and change the value on that BlendShape's line to the value you set in Unity. If there are two or more keys, change all of them.
  3. If the BlendShape doesn't need to be written, right-click its line and delete it with Remove Properties. If Write Defaults is ON, the value you set in Unity is used from then on. If it's OFF, the previous value may stay, so fix the value instead of deleting the line.
  4. Press Play with Gesture Manager, try all your hand gestures and menu items, and check that the value doesn't go back.
  5. Upload, and check in VRChat too.

Things to watch out for

  • Just changing a BlendShape in Unity can't beat the value the Animator writes. The same goes for BlendShapes changed by tools such as outfit tools.
  • If you use a tool to make expressions, change your usual expression in that tool. If you fix FX directly, your changes are undone when the tool rebuilds it.
  • Installing an update to your avatar may undo the clips you fixed. Check again after an update.
  • Don't mix Write Defaults ON and OFF in the same controller. It becomes hard to tell which values stay.

Summary

  • The Animator isn't running in Unity's editor, but it runs in VRChat.
  • If a BlendShape is written in any clip, the Animator decides its value, not the value you set in Unity.
  • When it isn't in the clip, you get the value you set in Unity if Write Defaults is ON, and the last value if it's OFF.
  • Press Play with Gesture Manager to check, and fix the value in the clip that causes it.
