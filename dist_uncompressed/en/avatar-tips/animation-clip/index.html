Avatar Tips #7

Making animations

When a gimmick changes how something looks, you write what changes, and how, in an animation clip. This tip explains what's inside a clip, what you can move from FX, how to make clips by recording in Unity, how to place keyframes, and how to fix a broken path that shows "Missing!".

Read this when

  • You want to build a gimmick, but you don't know how to make an animation clip.
  • You want to know what an animation can move.
  • Items in the Animation window turn yellow and say "Missing!".
  • You recorded a clip, and it ended up moving things that have nothing to do with it.

What is an animation clip?

An animation clip (clip) is a file that says which property of which object to set to what value, and when. Its extension is .anim. You use it by putting it in an Animator state. #6 How the Animator works explains how states and clips relate.

The Animator writes the values in the current state's clip to the avatar every frame. As long as it stays in that state, it keeps writing the same values.

For example, the clip Hat_ON, which shows the hat, contains just this one row.

Path (which object)TypeProperty (what)Frame 0Frame 1
Accessories/HatGameObjectIs Active1 (on)1 (on)

Each row (property) is made of a path (which object in the avatar) and a property (what to change on that object). A mark in the row for the value at a certain time is called a keyframe (key).

In the Animation window, this row appears as Hat : Is Active: the last name in the path, then the property name.

For an on/off gimmick, make both a clip that shows the hat (Hat_ON) and a clip that hides it (Hat_OFF). There are ways to skip the off clip, but then how it behaves depends on the Write Defaults setting. If you make both, it works the same whether Write Defaults is ON or OFF (#13 It looks different in Unity and VRChat).

What to move from FX, and what not to

Most gimmick clips go into the FX controller. From FX, you can move almost anything except Humanoid bones (muscles). If you move BlendShapes or materials from a slot other than FX, they aren't copied to the avatar in the mirror (#6 How the Animator works).

When you move material values, you move values of the shader your avatar uses (such as lilToon). If you change the shader, a value with the same name may no longer exist, and the clip may stop working.

To change something gradually (color or size) by turning a dial in the menu, use a Radial Puppet and Motion Time (#9 Switching in steps and changing gradually).

Making clips by recording

The easiest way to make a clip is to record it in Unity's Animation window. While recording, any value you change in the Inspector is written into the clip. Here you'll make Hat_ON, a clip that shows the hat, and Hat_OFF, a clip that hides it. Assume the hat (Hat) is a child of Accessories in the avatar, and is normally turned off.

Preparation: make the clips and the controller

  1. Make a folder for the gimmick in the Project window. Right-click inside Assets, choose Create → Folder, and give it a name (for example, Hat inside MyGimmicks). Keeping each gimmick in its own folder makes things easier to find later.
  2. Right-click inside that folder, choose Create → Animation, and name it Hat_ON. Make Hat_OFF the same way. In some Unity versions, it's at Create → Animation → Animation Clip.
  3. Right-click in the same folder, choose Create → Animator Controller, and name it Hat_FX.
  4. Double-click Hat_FX to open it in the Animator window. Drag the Hat_OFF and Hat_ON files into the graph. This makes two states with the clips in them. The Animation window only lets you pick clips that are in the selected Animator's controller, so turn them into states first.
  5. In the Hierarchy, select the top object of your avatar (the one with the VRC Avatar Descriptor). Drag Hat_FX into the Controller field of the Animator component in the Inspector. This is only temporary, for recording.

Record

  1. Open the Animation window with Window → Animation → Animation (or press Ctrl + 6). Keep the top object of your avatar selected in the Hierarchy.
  2. In the dropdown at the top left of the Animation window, choose Hat_ON.
  3. Press the red circle (the record button) at the top left. The timeline turns red, and recording starts.
  4. Make sure the white vertical line (the current time) is at frame 0. You can also move it by typing 0 in the time field.
  5. Select the hat (Hat) in the Hierarchy, and check the box at the top left of the Inspector to turn it on. A Hat : Is Active row appears in the Animation window, with a key at frame 0.
  6. Type 1 in the time field to move to frame 1. Select the Hat : Is Active row in the Animation window and press the Add Keyframe button (a diamond with a +). A key with the same value (on) is added at frame 1 too.
  7. Press the red circle again to stop recording.
  8. Choose Hat_OFF in the dropdown and start recording again. At frame 0, check the hat's box once, then uncheck it. Recording only adds a key when a value changes, so to record something that's already off as off, change it once and then change it back. Add a key at frame 1 too, then stop recording.
  9. Make sure the hat in the Hierarchy is back to how it was before recording (off). If it isn't, set it back with the checkbox in the Inspector.
  10. Set the Controller of the Animator component on your avatar's top object back to how it was (usually None). VRChat doesn't use this field. It uses the controllers in the Playable Layers slots. If you leave yours here, it's harder to tell which controller is the real one.
  1. The record button. While it's pressed, the timeline and the values you change in the Inspector are tinted red.
  2. Choose which clip to write to. It lists the clips in the selected Animator's controller.
  3. This row appears when you change the hat's checkbox while recording. The check means on (1).
  4. You can also add rows without recording. Press Add Property, choose the object and property, and press +.

BlendShape and material values are recorded the same way: change the value in the Inspector while recording. For a BlendShape, change the value in the BlendShapes section of the Skinned Mesh Renderer.

Everything you touch while recording goes into the clip. Don't move other objects or try out values while recording. To delete a row that got in, right-click it in the Animation window and choose Remove Properties.

When you connect with Modular Avatar's MA Merge Animator, you can also add an Animator component to the gimmick object and record there. The "Paths" section below explains this. #8 Building a menu toggle shows how to connect it to your avatar.

Keyframes and clip length

A keyframe marks the value at a certain time. Between keys, Unity fills in the values smoothly. If you put a key of 0 at frame 0 and a key of 100 at frame 60, you get a clip that changes from 0 to 100 over 1 second (when 1 second is 60 frames).

In an on/off clip, the value doesn't change. The hat stays out the whole time it's shown. So two keys with the same value, at frame 0 and frame 1, are enough. The length is almost 0, but as long as it's in the state, the Animator keeps writing this value.

A single key usually works too. But a clip with a length of 0 can be awkward to handle, for example when you use Motion Time. Two keys are the safe choice.

For things that change in steps (turning a dial to change color, changing size little by little), put keys with different values at the start and the end, and use the Animator's Motion Time to choose which part of the clip to show. #9 Switching in steps and changing gradually shows how.

Paths and fixing "Missing!"

Each row in a clip says which object to move, using a path. The path is the chain of names, joined with /, from the object with the Animator you selected while recording down to the object being moved. If you recorded on the top object of your avatar, the hat's path is Accessories/Hat.

A path depends only on names and positions. If you rename the hat or move it under another object after recording, the clip can no longer find it. When this happens, the row in the Animation window turns yellow and shows something like Hat : Is Active (Missing!). In VRChat, that row doesn't move anything either.

Names are case-sensitive. Just changing Hat to hat is enough to break the path.

  1. The clip says Accessories/Hat, but there's no object named Hat in that place. The row turns yellow.
  2. The hat was renamed to Hat2, so the path no longer matches.

How to fix it

  1. The surest fix is to put the name and position back to how they were when you recorded. Rename the hat back to Hat and put it back under Accessories, and the yellow warning goes away.
  2. If you want to keep the new name or position, edit the clip's path instead. Select the yellow row in the Animation window and press F2 (or click it twice, slowly) to edit the path. Enter the current name and position (for example, Accessories/Hat2).
  3. After editing, check that the yellow warning is gone. The key values stay as they were.
  4. Check whether other clips move the same object. If you fixed Hat_ON, fix Hat_OFF the same way.

Paths when connecting with Modular Avatar

When you connect a controller to your avatar with Modular Avatar's MA Merge Animator, the Path Mode setting changes where paths are counted from. With Relative (the default), paths are read from the object that has MA Merge Animator. With Absolute, paths are read from the top object of the avatar (Modular Avatar's Merge Animator page (opens in a new tab)).

When you use Relative, add an Animator component to the gimmick object (the object you put MA Merge Animator on), select that object, and record. Paths are counted from that object, so they're less likely to break when you move the gimmick to another avatar. If you check "Delete attached animator" in MA Merge Animator, the Animator you used for recording is removed automatically when you upload.

To move something outside the gimmick object, like a hat that came with the avatar, record on the top object of the avatar and set Path Mode to Absolute.

Common problems and fixes

A row turns yellow and says "Missing!"

What happens
In the Animation window, a clip row turns yellow and (Missing!) appears after its name. That part doesn't move in VRChat either.
Cause
You renamed or moved the object after recording. Or you've selected a different object with an Animator than the one you recorded on.
Fix
Put the name and position back to how they were when you recorded, or select the row and press F2 to edit the path. Also check Path Mode in MA Merge Animator.

You can't press the record button, or no clips appear

What happens
The Animation window shows no record button or clip dropdown. Only a "Create" button appears.
Cause
You haven't selected an object with an Animator component in the Hierarchy, or that Animator's Controller is empty.
Fix
Select the top object of your avatar, and put a controller that contains your clips in the Animator's Controller field. Don't press Create here. It makes a new controller and puts it in.

Unrelated things move too

What happens
It's a clip for showing a hat, but playing it also changes your expression or clothes.
Cause
You touched other objects or values while recording, so those rows got into the clip too.
Fix
In the Animation window, right-click the rows you don't need and choose Remove Properties.

After you stopped recording, the object in the scene had changed

What happens
Nothing went into the clip, and the hat in the Hierarchy stayed on.
Cause
You changed the value before pressing the record button (while not recording). Changes made while not recording change the object in the scene itself, not the clip.
Fix
Set the value back in the Inspector. Make sure the record button is red before you change values.

You moved arms or fingers, but they don't move in VRChat

What happens
You made an arm or finger pose in a clip, but it doesn't move when you put it in FX.
Cause
Humanoid bones (muscles) don't move from FX.
Fix
Move hand shapes with the Gesture controller, and whole-body motion with the Action controller (#6 How the Animator works).

A clip that changes color doesn't work

What happens
You made a clip that changes a material's color, but the color doesn't change in VRChat.
Cause
You changed the material's shader after making the clip, so a value with that name no longer exists. Sometimes the clip is moving a value on a different material (slot).
Fix
Record again with the current shader. Also check whether the row in the Animation window has turned yellow.

Things to watch out for

  • When you finish recording, always press the record button to stop. If you keep working while recording, everything you touch goes into the clip.
  • Don't change the names or positions of objects your clips use. If you do change them, fix the clip paths too.
  • When you're done, put back the controller you placed in your avatar's Animator for recording.
  • Use Is Active to show and hide things. Hiding something by setting its scale to 0 means moving a Transform from FX, which VRChat's official docs don't recommend.
  • Make both an on clip and an off clip. Then it works the same no matter how Write Defaults is set (#13 It looks different in Unity and VRChat).
  • Before you edit clips that came with an avatar or outfit you bought, make a copy first.

Summary

  • A clip says what (property) of which object (path) to set to what value, and when (keys).
  • From FX, you move on/off, BlendShapes and materials. Humanoid bones don't move.
  • Make clips by recording in the Animation window. Everything you touch while recording goes into the clip.
  • For an on/off clip, keys with the same value at frames 0 and 1 are enough.
  • Renaming or moving an object breaks the path and shows "Missing!". Put it back, or edit the path with F2.
  • Next, you'll use the clips made here to build a gimmick you turn on and off from the menu (#8 Building a menu toggle).
