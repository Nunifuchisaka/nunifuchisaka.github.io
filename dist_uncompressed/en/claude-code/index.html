How I use Claude Code

My VRChat assets — shaders and avatar gimmicks — their manual sites, and this site are all made with Anthropic's Claude Code at the center, sharing the work with OpenAI's Codex. Here is how my agents are set up and how each kind of work moves from idea to release.

Setup

Me

Asks for things in plain Japanese and picks from the options offered

Claude Code

Reads the request, hands the work to the subagents and Codex, and reports back

Agents

意匠家 and 技師 are defined as Claude Code subagents (.claude/agents). Codex is called from inside Claude Code.

  • 意匠家 (Ishōka) Design

    Proposes the direction before any code is written: for a page, the palette, type and wireframes; for an asset, how it should look. It only makes proposals and never writes code.

  • 技師 (Gishi) Implementation

    Writes the code and checks it: the site's HTML and CSS, shaders, Unity editor extensions and gimmick setups. Through MCP for Unity it works in the Unity Editor directly.

  • Codex Review and parallel work

    OpenAI's coding agent, called from inside Claude Code. It reviews the code and plans Claude Code writes, and takes on separate pieces of work in parallel.

Skills

  • Frontend Design

    Anthropic's official skill for design that doesn't look templated. Added on October 31, 2026.

  • booth-product-site

    A skill of my own for making the manual sites for my BOOTH products.

  • Superpowers

    A set of skills for how to build, by Jesse Vincent and Prime Radiant. I use brainstorming (answer questions until what I want is clear), writing-plans and executing-plans (write an implementation plan and follow it), and test-driven-development (write the tests first, then the code).

Project notes

  • CLAUDE.md

    Kept in the repository: how the site is structured, the build commands, and the class naming rules. It also says to always reply in Japanese.

MCP

  • MCP for Unity

    An MCP server by CoplayDev that connects Claude Code to the Unity Editor. 技師 uses it to read console errors, edit scenes and prefabs, run menu items and my own tools, and take screenshots to check the result.

Rules I keep

  • Confirmations and approvals are multiple choice.
  • Anything that couldn't be verified is written down as such.
  • No force pushes.
