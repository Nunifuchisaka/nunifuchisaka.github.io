Claude Code の使い方

VRChat用のアセット（シェーダーやアバターのギミック）とその説明書サイト、そしてこのサイトを、AnthropicのClaude Codeを中心に、OpenAIのCodexとも分担しながら作っています。エージェントの構成と、それぞれの作り方を紹介します。

構成

ぬにふちさか

やりたいことを日本語で伝え、出てきた選択肢から選ぶ

Claude Code

依頼を読み、作業をサブエージェントやCodexに任せ、結果を報告する

エージェント

意匠家と技師は、Claude Codeのサブエージェント（.claude/agents）として定義している。CodexはClaude Codeの中から呼び出す。

  • 意匠家 デザイン

    コードより先に方向性の案を出す。サイトなら配色・書体・ワイヤーフレーム、アセットなら見た目の方向性。案を出すだけで、コードは書かない。

  • 技師 実装

    コードを書き、自分で確かめる。サイトのHTMLやCSSも、シェーダーやUnityのエディター拡張、ギミックの構成も。MCP for Unityを通じて、Unityエディターを直接操作する。

  • Codex レビュー・並行作業

    OpenAIのコーディングエージェント。Claude Codeの中から呼び出し、Claude Codeが書いたコードや計画のレビューと、別々の作業の並行を任せる。

スキル

  • Frontend Design

    テンプレート感のないデザインのための、Anthropic公式のスキル。2026年10月31日に導入。

  • booth-product-site

    BOOTHの商品の説明書サイトを作るための、自分用のスキル。

  • Superpowers

    Jesse VincentとPrime Radiantによる、作り方の手順をまとめたスキル集。よく使うのは、brainstorming（質問に答えながら、やりたいことを固める）、writing-plansとexecuting-plans（実装計画を書き、それに沿って進める）、test-driven-development（テストを先に書いてから作る）。

プロジェクトの覚え書き

  • CLAUDE.md

    リポジトリに置いている指示書。サイトの構成・ビルドの手順・クラス名の付け方を書き、「常に日本語で応答する」と決めている。

MCP

  • MCP for Unity

    CoplayDevのMCPサーバー。Claude CodeとUnityエディターをつなぐ。技師はこれで、コンソールのエラーを読み、シーンやプレハブを操作し、メニューや自作のツールを実行し、画面を撮って確かめる。

サイトを作る流れ

  1. ぬにふちさか

    依頼する

    やりたいことを日本語で伝え、brainstormingのスキルの質問に答えながら固める。

  2. 意匠家

    案を見る

    コードを書く前に、配色・書体・ワイヤーフレームなどの方向性の案を出してもらう。

  3. ぬにふちさか

    選んで承認する

    確認はいつも選択式。おすすめが先頭に来る。

  4. 技師

    計画を書く

    writing-plansで実装計画を書き、executing-plansでそれに沿って進める。

  5. 技師・Codex

    作って確かめる

    別々の作業はCodexにも分けて、並行して進める。ビルド・HTMLの検証・ライトとダーク、PCとスマホのスクリーンショットで確かめる。

  6. Codex

    レビューする

    技師が書いたコードを、Claude Codeから呼び出したCodexがレビューする。

  7. ぬにふちさか

    報告を読む

    確認できなかったことも、はっきり書いてもらう。

VRChat用アセットを作る流れ

DeepFrostIceのようなシェーダーや、アバターのギミックも、同じ体制で作っています。Unityの中の作業は、技師がMCP for Unityを通じてUnityエディターを直接操作して進めます。

  1. ぬにふちさか

    依頼する

    作りたいシェーダーやギミックを日本語で伝え、brainstormingのスキルの質問に答えながら固める。

  2. 意匠家

    方向を決める

    見た目の方向性の案を出してもらい、選択式で選ぶ。

  3. 技師

    計画を書く

    writing-plansで実装計画を書き、executing-plansでそれに沿って進める。

  4. 技師・Codex

    作る

    シェーダー、導入を助けるUnityのエディター拡張（Fit To AvatarやRefitのボタンなど）、Modular Avatar用のギミックの構成を作る。シーンやプレハブへの組み込みも、MCP for Unityで行う。テストを書けるものは、test-driven-developmentでテストを先に書いてから作る。別々の作業はCodexにも分けて、並行して進める。

  5. Codex

    レビューする

    技師が書いたコードを、Claude Codeから呼び出したCodexがレビューする。

  6. 技師 → ぬにふちさか

    確かめる

    技師がMCP for Unityで、コンソールのエラーを読んで直し、Fit To Avatarなどの自作ツールを実際に動かし、シーンの画面を撮って確かめる。最後にぬにふちさかがUnityとVRChatで実際に試す。

  7. Claude Code

    説明書を書く

    説明書サイト（日本語と英語）とBOOTHの商品ページを書く。ポリゴン数などは実測値に合わせて直す。

決めているルール

  • 確認や承認は選択式にする。
  • 確認できなかったことは明記する。
  • force push はしない。
